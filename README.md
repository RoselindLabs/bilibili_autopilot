## Neko生态接入

0.13.5选择性移植上游的任务级HTTPX传输与SDK2.22说明布局兼容测试。账号验证、读取及WBI/buvid/ticket准备使用插件自有HTTPX会话，TLS证书及主机名校验开启；不切换库全局客户端。读取会话在插件创建时继承库的代理、trust_env及超时，环境代理仍按HTTPX规则处理；二维码、字幕/封面及单次评论POST沿用原客户端。没有新增网络重试或配置字段；生产尚未发现同类curl77故障，不将此兼容改进当作线上故障修复。

0.13.4在手记模式下，即使当轮只剩1条阅读额度，也提供最多10条已过滤候选元数据供挑选；提示和解析同时限制实际remaining，超额选择无效且不补调用。实际阅读额度、同UP/题材限制与原模型调用链保持。

分享素材新增可选 `evidence_quote`（≤400字符），桥入口按实际正文的NFKC/大小写/字母数字归一化再次核验，保原引用，不代表平台事实已核实。精确定位时summary保留引用附近上下文（≤480字符）；只能归一化匹配则沿用正文开头。旧素材缺字段继续兼容，不联网回填。Proactive配套应在原正文摘录240字符内先引用、后上下文，整段仍≤1600字符（含JSON转义/字段开销）；B站侧不修改消费端、签名、180秒租约或分享机会。

手记新增 `diagnostic={stage,reason_code,read_warning}` 固定分类，以及 `material_registration={status,reason_code,registered_at}` 实际登记结果，均存在原payload，无新表。只依据真实分支/异常类型，不保存原始异常、猜测旧失败或细分无证据的封面错误。旧条目缺字段显示未知，注册异常可能已写入素材，因此记unknown而非宣称未登记；不恢复重试。

“阅读与素材状态”在现有手记条目内按需展开。素材available仅表示匹配本条手记的现存资料未超过48小时，不表示目标聊天可领取；expired须有可靠时间，not_registered须有明确未登记结果，缺库/旧信息/不明缺失为unknown。诊断连接只读、不建表、不清理；机会计数按当前账号＋视频所有历史汇总，非单手记送达归因，shown只是已提供资料，不是sent。原unknown/消费墓碑不变。

0.13.2为历史查询工具补充 `platforms="qq"`：支持平台过滤的 Host 不向 TG 会话展示或执行，共享 Focus 保留已授权 QQ 分支。原 QQ 名单、账号核验及分享/unknown 行为不变，未新增 TG 分享。SDK2.22.1 / Host `f53828ef` 的真实注册→查询/执行过滤→混合平台 Focus 路由已离线合成验证；合成通过不代表真实聊天验收。

0.13.1统一手记和旧浏览投影的终态，保存经ID核验的详情元数据；初始化只修正已有投影，不重读、不补额度或发送。领取后素材消失显示不可用，保留原机会计数及防重。封面解码在后台线程完成，仍由唯一浏览轮次持锁；6秒为协作期限，超时/取消须等实际解码结束才释放轮次，线程不能强杀。正文和封面仍进入同一次原模型请求，提示策略不变。下载继续保留现有域名白名单、HTTPS及禁止重定向，未新增DNS固定或改变代理配置。

关闭 `comment.publish_enabled` 时，自主阅读走独立手记流程：读正文、一次逻辑感想生成、保存记录，不再生成/复核评论草稿。可有感想，也可没有；不为凑满额度阅读。原有明确手动 `preview` 保持旧预览用途，不混入自主手记。

手记按次保存在原 `state.sqlite3` 的新journal表，旧记录不回填。保留时间、正文依据、当时感想和真实历史关联，最多2万条，满额暂停新浏览，不自动删旧内容。历史按同视频最多2条、相同视频题材最多4条、同UP最多2条、近期最多6条依次去重选取，最终最多10条且序列化上下文不超过4000字符（预留时区时间文本）。空题材/未知UP不视为相关；这是元数据匹配而非语义检索，同UP不代表观点相关。成功阅读一周后再次被推荐时可重看，新增记录而不覆盖。失败/中断的感想不自动重试，原评论unknown与防重账本保留。

人设仍由插件读取宿主的`personality`正文与`reply_style`，合并后沿原4000字符上限进入提示词；设为replyer任务只借模型路由，不自动注入聊天Replyer全部上下文。当前维护实例只读长度核对未触发截断，未修改线上人设或模型配置。

感想更偏自然随笔：从具体细节说起，允许偏好、吐槽、疑问和短句，不要求每条总结意义。读取正文后，将经视频ID核验详情中的封面缩至768px以内，与文字一起交给原感想模型（须支持图片）；不额外调用视觉总结。仅下载固定B站CDN公开图片，6秒/2MiB/800万像素上限，失败则文字继续。封面是静态宣传资料，不当作看过视频；原文依据仍须来自字幕/摘要。图片只在请求内存中使用，保存cover_provided标记表示曾附图，不证明模型实际理解。原候选失败策略保留，不额外去图补发。

插件页只保留「B站手记」一个侧栏入口，内部「手记／管理」互斥展示。手记默认读感想与读过记录，可按日期、关键词和结果筛选；依据与先前感想按需展开。删除仅在「整理手记」中出现。管理页保留账号、运行配置回显、容量、旧历史单层折叠、评论核对和明确标注会调用模型的旧预览。只打开页面不会刷视频或调用模型。

每条手记可删除；「整理手记」支持勾选批量删除（一次最多200条），或清理当前B站账号全部日期的失败／中断记录。先核对数量与标题，再确认永久删除；正在阅读的条目不能删除。删除清空正文、感想、依据、相关手记中保存的原文副本及对应待分享素材，关联位置显示“原记录已删除”；释放2万条内容容量，只保留账号／视频／条目编号及时间防重标记，禁止因此自动重读。评论、发送结果未知、分享防重与用量账本保留；已进入聊天请求或发出的内容及既有运维备份不会被撤回或清除。删除不自动解除满额或人工暂停，整理后可手动恢复浏览。

`ecosystem.enabled=true`时，有真实感想且留下分享缘由的阅读进入原素材桥。Neko Proactive 2.9.4会结合具体聊天选择是否采用，不强制分享、不新建调度器。QQ群仍取双方授权交集；私聊须明确设置 `ecosystem.qq_friend_ids`（默认空）且主动插件也允许该好友，账号与真实会话必须匹配。新增 `chat.get_private_streams` 仅用于解析这些明确授权的已有会话，不创建聊天或自动授权好友。

仍只有原主动调度器决定何时聊天；每视频/群最多一次素材机会，180秒临时提示只展示一次，
下一轮清理，不把正文塞进持久任务原因。默认同聊天每天2次/至少180分钟可配置，是素材上限，不是发送目标。
`shown/submitted/unknown`不代表QQ收到，未知不重放。生态模式抑制原直接评论后发群以免双发，
B站评论/跟进仍按原开关和账本运行；不复制Life名单、不回放历史浏览。

### 哪些配置影响手记

在宿主「插件管理」找到「Neko B站手记」并打开配置。原生配置页分为「浏览／模型分工／分享机会／旧功能与高级」，使用原生保存；自定义手记页只说明入口，不另存一份配置。宿主当前导航桥不能从custom页直达原生配置页。

- **浏览**：节奏、跨午夜/全天活动时段、每轮/每日视频上限、时长、兴趣与过滤。秒字段保持原单位，600秒＝10分钟；最长间隔仍以分钟填写，整组校验最短≤最长。上限不是目标。
- **模型分工**：`model`为共用默认，`decision_model`仅自主判断刷不刷/选新片/下次考虑，`reflection_model`仅自动手记感想。新增任务空、候选空、时限/正文预算0均继承共用值；升级不自动换Planner。阶段候选非空覆盖共用候选，候选优先于任务自选；`use_task_models=true`明确忽略两级候选，改用最终任务选模。
- **预算**：单候选时限两阶段均继承；自主判断外层保持「单候选时限×候选数＋5秒」，共用`decision_budget_seconds`原本不限制自主判断。感想继承该总时限和正文字符预算，也可单独覆盖。Host任务的输出token预算保持，不增加审核/润色模型链。借用planner仅借模型路由，不进入聊天Planner循环或自动带聊天上下文/工具。
- **分享机会**：群/私聊分别按北京时间计算素材机会，不是QQ发送频率；仍取双方授权交集。群名单`share.qq_group_ids`保留原路径。旧评论使用兴趣分；手记有感想且有分享缘由时兼容分为1，否则0，并非模型打分。
- **旧功能与高级**：评论开关开启会把自动轮次切回旧评论流程；评论长度/最低兴趣/冷却、评论候选池、风格/依据复核不控制感想。跟进开关开启可独立检查并调用模型，发送还需评论开关；要停该链应关闭跟进。直接QQ分享/润色仅生态关闭且新B站评论提交成功后使用。升级保留所有现值。

管理视图显示插件当前接受的节奏、阶段模型和旧功能开关，可在原生保存后刷新核对；保存成功与运行时已采用是两回事。本版没有新增原生保存CAS或跨节事务，也不修改Host/Dashboard。页面筛选、选择和视图仅保内存，换号/退出清除，刷新不恢复。

`读取 AI 摘要…code=-504，已使用字幕`表示平台摘要服务调用超时后成功读取字幕，不等于账号/权限被拒绝。0.8.1将超时、服务异常、登录/权限及风控/限流分开显示，旧记录仅修正页面文案、不改历史账本；原字幕回退/暂停/重查与评论发布规则不变。

0.9.0同步正式上游v0.8.0：评论冷却/额度用完时只保存兴趣候选，可发送时独立选片并重新读取、判断及复核，允许不选。该调度只负责B站评论，不新增QQ主动调度；上游v0.7.2的较长群分享文案仅作用于生态关闭时的旧直接分享路径。配置键、依赖及表结构不变，保留既有发布开关，不覆盖本地配置或账本。

0.9.1合入上游v0.8.7（含v0.8.3～v0.8.6）：活动事实查询、选片上限、脱敏登录诊断与未知发送期间继续浏览。维护版排除实验NapCat小程序卡片、相关权限和数据库迁移；保留原配置版本/数据及现行同SHA发布门禁。旧版已暂停的实例仍需管理员明确恢复，不自动解除unknown或补发。

麦麦独立插件 `local.bilibili-autopilot`。登录指定账号后，按既有自动启动设置进入自主模式：先结合人设、兴趣、时间和真实手记决定刷不刷，再形成感想。维护实例已关闭自动评论与跟进；旧发布代码与历史仍保留供兼容，不因更新开启。

## 主要功能

- 读取首页推荐，过滤广告、直播、重复视频、过长视频、屏蔽词和指定 UP 主。
- 自主模式下先判断浏览意愿，可以去刷，也可以休息；下次考虑的时间由模型决定，受最短检查间隔约束。休息决定和下次检查时间持久化，重启不会立即重复刷。当前不读取群聊忙碌状态或真实情绪。
- 优先读取 B 站 AI 摘要；没有摘要时读取字幕。准备评论时按主题补充字幕并复核正文。没有足够内容或为多 P 视频时跳过，不凭标题编造观后感。
- 模型使用麦麦的 `personality`、`reply_style`，可补充兴趣和评论风格；允许自然地“看过不评论”。
- 校验模型结构化输出和引用的视频原文，只有达到兴趣阈值时才考虑发表评论。
- 发布视频下的一级评论，并可跟进别人对麦麦已发送评论的回复；不点赞、不投币、不发送弹幕。
- 聊天中可查询自己的 B 站浏览、评论与跟进记录，区分真实发送、预览草稿和未知结果；升级前已有记录也能检索。
- 这里的“浏览”是读取和理解推荐视频内容，没有启动播放器，也不会上报播放时长或增加观看历史。推荐由账号的现有 B 站推荐服务提供；本插件不会自动训练账号的观看历史。
- 不做音频转写或视频帧分析；手记可参考静态封面。AI 摘要可能有误，长字幕在配置上限内抽取相关内容及开头、中段和结尾，并保留时间位置。

## 在聊天中回忆 B 站活动

在现有 `share.qq_group_ids` 授权的QQ群中，可以问麦麦“最近刷了什么 B 站视频？”、“你在深海视频下面评论了什么？”或“最近在 B 站回复了什么？”。插件提供只读工具 `bilibili_autopilot_history`，供聊天模型按标题、UP 主、BV 号、主题、感想、原文引用或评论关键词检索；默认最近 7 天、最多 8 条，可以扩大时间范围或用 `days=0` 查询全部历史。关键词逐字段字面匹配（沿用SQLite lower的大小写语义），不检索JSON键名、不把字段首尾拼成命中。

0.13.3支持继续查同关键词的更早记录：有更多时返回 `next_cursor` 和 `next_call`（工具名与query/kind/days/limit/cursor参数）。按 `next_call.arguments` 续页；若当前Schema要求 `session_id`，保留上次调用相同真实 `session_id`，其余参数原样。每页最多20条，序列化records不超过12000字符，长字段为摘录。游标绑定本次真实QQ会话、授权/账号及全部过滤条件，固定首次查询的时间窗口与四张来源表的记录上界，同时间用唯一记录键排序，不因新记录插入或手记删除产生偏移跳项。每次仍读当前库，已删除手记不返回；这是有界续页，不是冻结所有正文/状态的数据库快照，已有旧浏览记录更新时间改变可能离开原窗口。共享Focus沿用本次宿主会话路由，不能借游标换聊天或账号；游标10分钟固定有效，重载、配置变化或改条件后须去掉cursor重新查。只读重用游标不消耗素材机会，不触发浏览、模型或发送，也不新增分页数据库/数据迁移。

查询和回复前交接均核验已有QQ会话、群／私聊名单及 `ecosystem.account_id` 账号限制；未授权聊天、身份歧义或查询中撤权时不返回资料。共享Focus按宿主reply路由及消息封套绑定真实目标，不能借另一聊天的问题注入。历史查询独立于主动分享，不领取签名素材机会，也不扩大Proactive的双侧授权；管理员原有命令权限保持。`kind=journal`查询手记，`browse`含新手记和旧浏览，`all`还包括旧评论／跟进。

0.13.3历史工具要求宿主支持并强制覆盖 `neko.tools.context.v1` 可信工具信封（维护Host N05契约），SDK须支持将该声明展平到注册metadata；最低SDK2.12.0支持。仅从信封中一致、非空的session_id/stream_id确定会话，忽略模型普通身份参数；QQ会话名单再次核验群/私聊目标及账号。普通/Focus信封account_id可为空，由真实已有会话补核；非空但矛盾则拒绝。未提供可信信封的旧Host明确失败，不降级采用模型stream_id。仅满足Host版本号不代表具有此维护契约。

该工具直接查询本插件的持久化活动记录，不需要重新积累历史，也不将后台活动伪造为 QQ 聊天消息或批量写入宿主通用记忆库。工具需要在主程序中启用；自然语言是否调用由聊天模型决定。可以明确要求“查询 B 站活动记录”，管理员也可使用 `/bili_auto history`。

查询成功后，插件会通过回复前钩子把具体标题、评论正文、内容依据和发送状态直接交给回复模型，避免规划器转述或长结果压缩时遗漏事实。回答本次 B 站经历以活动记录为依据，不用生活场景补写看过或听过的视频。事实摘要仅对当前聊天、当前目标问题有效，最多保留 5 分钟；新问题、账号变化、禁用或重载后不沿用旧摘要。

对于明确询问 B 站浏览或评论的问题，若规划器沿用旧聊天上下文而未重新调用查询工具，回复前也会从本地记录补充当前事实。该过程只读本地数据库，不请求 B 站或额外调用模型；无关闲聊不附加历史。

只有发送表确认成功的评论、跟进才标为已发布；预览、候选、失败、结果未知及仅解除阻塞的记录不会被当成已发布。查询只访问当前登录 B 站账号；暂停浏览时仍可查询，禁用插件或未登录时不返回聊天历史。新手记保留逐次经历，旧记录仍只保留各视频各模式的最新结果；标题或引用不足以证明完整看过视频。

升级会自动增加journal表和默认空私聊名单，不改现有开关、模型、时限、凭据与旧账。回退只退源码，保最新数据库与unknown；旧版不显示手记但不得恢复旧库抹除新记录。正常生成沿原模型候选与总时限，不增加独立润色/复核调用。失败记录只写错误类型，不保存原始模型错误或凭据。

## 安装与首次使用

### 插件市场

市场收录后，在 MaiBot WebUI 的插件市场搜索「B站自主浏览与评论」，选择兼容版本安装。版本列表以市场已收录的 GitHub Release 为准；仓库更新或创建 Tag 不代表已经上架。

### 手动安装

在 MaiBot 根目录执行：

```sh
git clone https://github.com/RoselindLabs/bilibili_autopilot.git plugins/local_bilibili-autopilot
```

重新加载插件或重启 MaiBot，Host 会根据清单安装依赖。需要手动安装时，在 MaiBot 使用的 Python 环境中执行 `uv pip install -r plugins/local_bilibili_autopilot/requirements.txt`。

Docker 部署请将仓库放在挂载到容器 `plugins/` 的目录，并在容器使用的环境中安装依赖。无需修改麦麦主程序。详细配置示例见 [config.example.toml](config.example.toml)，更新记录见 [CHANGELOG.md](CHANGELOG.md)。

### 首次配置

1. 在麦麦 WebUI 的插件管理中确认插件加载成功，并打开本插件配置。
2. 配置 `plugin.admin_users`，可直接填写 QQ 号，例如 `["123456"]`，保存时会自动补全为 `["qq:123456"]`。其他平台填写 `平台:用户号`；留空时普通聊天命令一律拒绝。Host 验证过的本地操作员仍可管理。
3. 私聊麦麦发送 `/bili_auto login`，使用 B 站客户端扫描二维码并确认。默认登录后自动开始，无需发送 `start`。凭据仅保存到本插件的私有数据目录，不读取其他插件账号。
4. 默认不发布评论；可用 `/bili_auto preview` 直接预览一轮，查看选片和评论效果。此命令跳过“刷不刷”的判断，始终只预览，不受发布开关影响。
5. 阅读手记无需开启 `comment.publish_enabled`。仅希望恢复旧自动评论时才开启；跟进由`replies.enabled`单独控制。`/bili_auto status`显示最近意愿与下次检查时间。

关闭发布开关时，后台浏览生成独立阅读手记。没有账号时等待登录；首次登录、保存了账号的首次运行或重新启用插件后，默认自动进入运行状态。手动 `pause`、退出账号和异常暂停均保留，不能被自动启动覆盖；手动暂停或异常排除后用 `start` 恢复。重启保留运行选择。关闭 `browse.auto_start` 后首次使用需手动 `start`；关闭 `browse.autonomous_enabled` 后恢复固定间隔浏览。

| 命令 | 用途 |
| --- | --- |
| `/bili_auto login` | 私聊扫码登录，3 分钟内完成 |
| `/bili_auto preview` | 浏览一轮，只预览，不发表评论 |
| `/bili_auto replies` | 检查别人对麦麦的回复并预览是否接话，不实际发送 |
| `/bili_auto start` | 手动或异常暂停后恢复运行；默认由麦麦决定刷不刷，不强制立即浏览 |
| `/bili_auto pause` | 暂停；已发出的请求仍可能完成，但不会继续发送下一条 |
| `/bili_auto status` | 账号、启停状态、今日额度、异常原因，以及最近自主决定和下次检查时间 |
| `/bili_auto history` | 最近的浏览判断和评论记录 |
| `/bili_auto logout` | 暂停并清除本插件登录态，保留去重历史 |
| `/bili_auto ack BV号` | 自行检查 B 站评论后，确认已核对未知发送结果；该视频仍不会重发 |

开始执行手动预览或登录后，会在当前聊天返回结果。自动轮次的详细记录写入本地，通过 `history` 查看，不主动往群聊发送每轮报告。

### 扫码登录失败排查

从 0.8.6 起，登录日志以 `B站登录诊断` 为标记，记录生成二维码、轮询扫码状态、扫码后账号验证及本地凭据保存阶段。等待扫码和等待手机确认仅在状态改变时记录，不逐次打印轮询请求。

二维码、轮询和账号验证均使用 `httpx`；账号验证通过任务级绑定使用插件专属会话，日志记录实际客户端。异常记录包含异常链类型、数值错误码、已知 TLS 错误类别及插件、Python、网络依赖版本；管理页和聊天结果也会显示失败阶段与安全摘要。日志不输出任意异常原文、Cookie、二维码密钥、请求地址、代理地址或本地证书路径。

遇到扫码确认后报 `SSLError` 时，按[维护发布流程](docs/PUBLISHING.md)更新后，仅在管理员需要重新登录时扫码并收集本次 `B站登录诊断` 的开始至失败日志和管理页错误摘要；无需上传登录凭据、二维码或完整环境变量。0.13.5继承上游curl77数值诊断并绕开curl的CA文件加载路径；HTTPX自身的证书错误仍失败关闭，不关闭TLS校验。不能用上游安装包覆盖本fork的生态改动。

## 插件扩展管理页

麦麦 WebUI 侧栏 **插件扩展 → B站自主浏览管理**，地址为 `/extensions/local.bilibili-autopilot/manage`。页面使用麦麦已有的登录权限，无需额外部署网页服务。

- 查看当前账号、运行状态、今日视频和评论额度、最近自主决定、暂停原因和下次意愿检查时间。
- 点击恢复、暂停、预览或扫码登录；也可在指令输入框填写 `/bili_auto start`、`pause`、`preview`、`login`、`status`、`history`。页面操作不往 QQ 或群聊发送消息。
- 登录二维码直接显示在页面，完成、过期或取消后隐藏；登录和预览在后台执行，页面每 5 秒刷新结果，刷新页面不会重复执行指令。
- 分页查看和搜索视频浏览、实际评论发送、自主浏览决定，以及收到的回复与跟进发送记录。所有记录按当前 B 站账号隔离，拟写评论与实际提交结果分别标识。
- 通过“检查回复（只预览）”预览接话效果；记录类型中可切换“收到的回复与判断”和“跟进回复发送记录”，查看对方消息、麦麦原话、拟写或已提交内容及判断理由。
- 发送结果未知时，先自行到 B 站核对，再在对应区域填写 BV 号并点击确认。退出账号使用页面专门的退出按钮。两个操作使用麦麦页面的确认提示，不能通过输入框跳过。

管理页不返回 Cookie、登录凭据或模型思考内容。刷新页面只查询本地状态，不触发浏览或模型调用。

### 记录表格与 WebUI 版本

视频与回复记录均保留完整 13 列，包含各项时间、完整评论、判断理由、评论 ID 和失败重查状态，不以摘要或点击详情替代原字段。支持横向滚动的 WebUI 会为各列保留可读宽度，超出页面的部分在表格内部左右滚动，长评论和理由在单元格内换行。

宿主滚动修复见 [MaiBot PR #2208](https://github.com/Mai-with-u/MaiBot/pull/2208)，目前为待合并补丁。滚动能力由 MaiBot 主程序的 WebUI 提供；插件 Release 只更新插件声明与业务代码，不会替换主程序的前端包。MaiBot 1.3.10 / Dashboard 1.9.4 的原始版本仍可能挤压这些列，需要更新到包含表格滚动修复的 WebUI。升级前端时应部署完整构建产物及对应资源文件名，随后刷新页面，避免长期缓存继续使用旧脚本或样式。


## 跟进别人对麦麦的回复

默认启用 `replies.enabled`。后台每 10 分钟检查一次“回复我的”通知，与刷视频的意愿判断和视频分析额度独立；手动暂停、退出账号或离开活动时段时不自动检查。可以发送 `/bili_auto replies` 或点击管理页“检查回复（只预览）”验证效果，此操作不发出任何回复。

只接收别人直接回复本插件已提交成功评论的通知，核对视频 ID、目标评论 ID 和根楼层，并排除麦麦自己发出的内容。别人继续回复麦麦的跟进内容时，也可以接话。不会自动接管本插件没有发送记录的手工评论、未确认成功的发送、无关楼层、私信或单独 @。

模型会读取麦麦人设、原评论、对方消息和最近六条本地讨论记录，自主决定是否接话。发送时以根评论 ID 和对方这条消息的评论 ID 定位楼层。默认每次检查最多处理三条、最多发送一条，每天最多分析 20 条消息和尝试发送 8 条跟进回复；分析与发送分别限额，预览计入分析额度。跟进回复距离最近一次评论或回复发送尝试至少间隔 15 分钟，每条根评论讨论长期累计最多跟进 3 次，失败也计入。上述参数均在“跟进别人回复”配置节中显示中文说明。

默认只跟进最近 72 小时收到的回复，每次最多读取三页通知。等待发送间隔或每日发送额度时，保留尚未分析的消息，之后检查时再考虑。模型超时或发送前被冷却拦截时，后续检查可重新判断；其他已完成判断的消息、每种预览/发布模式只分析一次；预览不消耗真实发送机会。

发送意图先写入数据库，签名后的 POST 只调用一次。请求超时、进程中断或结果未知时，仅暂缓评论和跟进回复发送；自主浏览继续，感兴趣的视频只保存候选，不提前生成正文。核对 B 站实际结果后使用页面核对按钮或 `ack BV号` 解除发送阻塞，被核对的消息仍不会重发。平台返回评论 ID 只表示接收，不保证最终公开可见。

## 旧直接评论后分享视频到群

本节直接发送只在 `ecosystem.enabled=false` 时运行；生态开启时群名单仍是资料桥授权，不能清空。`share.qq_group_ids` 默认 `[]`（不填群号，不分享）。在 WebUI「QQ群授权与旧评论后分享」中，每项填写一个麦麦已经加入、并有实际账号会话的 QQ 群号，例如 `123456789`，最多 10 个。只使用已有的真实群会话，不创建会话、不主动加群；多个账号的同群会话无法唯一确定时跳过并记下原因。

默认链接格式下，每轮浏览结束后，仅对本轮已提交成功的一级评论视频发送一条群消息，结合麦麦人设、刚发表的评论和视频内容依据，额外生成一段简短口语感想，再附上 `https://www.bilibili.com/video/BV...` 链接。文案不使用固定开场，不照抄标题，并参考近期分享避免重复句式。多个群共用同一条生成文案；生成失败只跳过本次分享，不暂停插件，也不会影响已成功的 B 站评论。预览、看过不评论、被限额拦截、平台拒绝、结果待核对和跟进别人回复都不会触发。平台接收评论不等于保证对外可见。

分享文案以“具体看点 + 感受或分享原因”为目标，通常为 2～3 句话、50～120 字，最多 180 字，再附上视频链接。素材不足时允许更短；润色保留看点和信息量，初稿与润色稿均经过内容依据复核，不凭空补充细节或亲身经历。

按 B 站账号、视频和 QQ 群持久化去重。同一视频对同一群只尝试分享一次；群消息失败、超时或进程中断均不自动重发，也不会回滚或重发已经成功的 B 站评论。配置后只对后续新评论生效，不补发历史视频。管理页显示目标群、最近结果，并可切换到「评论后群分享记录」查询历史。

## 默认配置

WebUI 配置表单中，每项均显示中文名称和常驻说明，包含时间单位、填写示例和调整数值的影响。配置格式版本由插件维护，只读展示；配置文件中的英文键名保持不变。

- 默认每次浏览意愿检查至少间隔 10 分钟（`browse.interval_seconds=600`），最多间隔 20 分钟（`browse.max_check_minutes=20`），模型在此范围内选择下次考虑时间，且每次都可决定不刷。调小最长间隔后，已有等待也会按新上限缩短；历史记录保留当时原定的时间。每轮最多分析 3 个视频，每天最多分析 180 个；手动预览也计入分析额度。意愿判断会额外调用一次模型，但不占用视频分析或评论额度。
- 意愿检查到期时先读取一次最新推荐标题、简介和时长，并提供历史记录的本地时间、距今分钟数与预览标记。休息期间不会反复拉推荐；选择不刷时不读取字幕或摘要、不占视频分析额度。历史几条不感兴趣不会被当作当前推荐的结论，模型仍可自由决定休息。
- `browse.explore_more`（更积极地探索新视频）默认关闭；开启后提示麦麦在有感兴趣的新推荐时优先尝试看一两条，不因近期没发表评论或管理员手动预览而一直休息。它不是固定浏览概率，不强制发表评论。发表评论的兴趣分门槛由 `comment.min_interest` 单独设置，例如 0.55 比默认 0.75 更容易允许具体、自然的评论；发送间隔由 `comment.min_interval_seconds` 控制。
- 每轮最多发布 1 条视频下一级评论，每天最多 12 次一级评论发送尝试；发送一级评论前距离最近评论或跟进回复至少相隔 45 分钟，失败也计入发送额度。
- 一级评论与跟进回复的每日发送上限均可填 1～200，分别统计；这是插件配置范围，不代表平台承诺的发送额度。评论额度用完或处于冷却期间时，继续自主浏览，只判断兴趣并保存视频、想聊的点和少量内容引用，comment 必须留空，不提前生成正文或做正文复核。评论候选独立于浏览意愿检查：冷却结束且有额度时，从按兴趣、新鲜度和等待时间排序的最多10条候选中，由模型选当前最想聊的一条，也可以一条不选。选中后重新读取、生成和复核；没有兴趣或依据不足时放弃，不发送旧草稿。候选选择与重新分析仍受活动时间、暂停、分析额度、发送限额和持久化去重约束。管理页分别显示下次浏览检查状态和最早可再次评论的时间，检查时间已到时显示等待调度或当前任务完成。手动预览仍可执行。一级评论与跟进回复都以最近一次评论或回复发送尝试计时；默认分别等待 45 分钟和 15 分钟。发送上限不是目标发送量，实际发送还受模型意愿、分析额度、发送间隔和单条讨论跟进次数等条件限制。
- 活动时间 09:00–23:00，时区 `Asia/Shanghai`。结束小时为开区间，开始与结束相同表示全天，可设跨午夜时段。
- 超过 20 分钟的视频跳过；兴趣分低于 0.75 不评论，评论最多 160 字。
- 兴趣留空时，基于麦麦人设和账号推荐判断。可以填写具体喜好或在屏蔽词中排除话题。
- 默认使用 Host 的 `replyer` 模型，最大输出 token 数沿用该任务的配置（包括模型的思考用量）。可用 `model.candidates` 填写已有的具体模型名，按顺序逐个尝试；留空时由 Host 任务选模。每个模型分别使用 `model.timeout_seconds` 计时，超时、空正文或模型服务返回失败时切换到下一个；同一次生成中每个候选最多尝试一次。全部失败则跳过本条，后台保持运行，并安排有限重查。评论或跟进回复的判断未通过校验时，带着具体错误类别重新生成一次，继续严格校验字段、长度及内容引用；不会直接修补原文后发送。生成最多两组候选，每个准备评论的正文另做依据复核；所有步骤受总超时预算限制，重新检查也计入每日分析额度，不使用额外模型密钥。若提示只有思考内容、没有评论正文，请检查该任务的最大输出 token 上限。

去重按 B 站 UID 隔离，同一账号同一视频只允许一次发送尝试，另有文本归一化去重和近期相似度检查。预览不会占用发送机会；已完成判断的视频不重复分析，冷却等待及明确未发送的临时失败允许按规则重新判断。停止后重新启动、重启容器或重新登录同一账号都不会清空历史。

## 异常和数据

每次发布前以 SQLite 事务保存发送意图并校验每日限额与间隔。只调用一次签名后的评论 POST，请求超时或返回格式无法确认时记录为 `unknown`，绝不自动重试。进程中断留下的 `pending` 在重新加载时转换为 `unknown`。待核对仅阻止新的评论及跟进回复发送，不暂停自主浏览或手动预览；浏览意愿、活动时段、分析额度和候选有效期照常生效。重新启动允许恢复浏览，但不会自动核对或解除发送保护；人工暂停仍需管理员恢复。

视频信息、AI 摘要、字幕列表和字幕下载分别记录错误阶段。AI 摘要返回 `code=-504`、超时或网络连接失败时继续尝试字幕；字幕有效时保留摘要错误提示并使用字幕。如果没有可用字幕或内容仍读取失败，跳过该视频并继续处理其他视频。平台风控拒绝、登录失效及程序或配置异常仍会暂停，详情见 `status`。

读取异常同时覆盖 B 站库包装的 HTTP 错误，以及当前网络客户端的连接错误和超时。HTTP 408、5xx 可有限重查；HTTP 401、403、412、429 仍暂停处理，不通过字幕降级绕过登录或风控拒绝。

明确未发送的临时读取失败、模型调用失败、模型超时和判断校验失败，首次失败后至少等待 10 分钟重查一次；第二次失败后至少等待 20 分钟，最多再查两次。每次重查重新读取内容并生成判断，计入当天的视频或跟进分析额度；重启不会重置次数。正常选择不评论、无内容且没有临时错误的视频不重查。旧记录缺少视频元数据时，只能等待该视频再次进入推荐。存在任何发送尝试的视频及已尝试跟进的消息不自动重发；未知结果仍需先在 B 站核对，再用 `ack` 解除阻塞，解除不会清除去重记录。API 返回评论 ID 仅表示平台接收，不保证最终对外可见。

在读取或模型判断阶段退出、重载时，下次加载会恢复尚未尝试发送的中断分析；中断计一次失败，已用分析额度保留，仍受重查次数与等待间隔限制。重复加载不会重复增加失败数。重查及冷却等待队列先按当前筛选条件过滤，再取本批视频，被屏蔽或不符合时长条件的记录不会挡住后续视频。

管理页分别展示首次浏览或收到回复时间、状态更新时间和发送尝试时间，以及失败次数和最早重查时间。旧版只保存首次时间，升级时仅用已有发送记录补入可确认的时间，不推测缺失的更新时间。每日分析数按每次实际分析累计，状态更新和候选选片本身不重复计数，选中后重新读取判断计一次分析。候选池默认最多24条、有效期48小时；超限按兴趣、新鲜度和等待时间择优保留。管理页区分“候选保留中”“本次未选中，仍保留候选”“候选池已满，择优淘汰”和“超过有效期”。历史容量淘汰仅在时间戳能证明尚未到期时更正显示，不恢复已淘汰任务。

数据使用 `ctx.paths.data_dir`，包含 `credential.json` 和 `state.sqlite3`。登录凭据以仅当前用户可读写的文件保存，仍是本地明文，应保护运行目录。运行日志不写 Cookie、完整请求参数或模型提示词。自主决定、下次检查时间、评论历史和依据类型仅写入插件数据库，按 B 站 UID 隔离。

需要 Python 3.10+、MaiBot 1.3.10+、SDK 2.12+。Python 依赖同时列在清单、`pyproject.toml` 和 `requirements.txt`。为使用现有 WBI 签名准备而避免发送重试，`bilibili-api-python` 固定为实际验证的 17.4.2；升级该依赖时需重验签名测试。插件不改动麦麦主程序。

## 数据与权限

插件只申请模型生成、人设配置读取、文字/图片发送以及已有 QQ 群会话查询能力。扫码二维码仅通过管理员私聊或受麦麦登录保护的管理页展示。

`config.example.toml` 是不含账号和群号的默认示例；`config.toml` 是各自部署使用的本地配置，不进入源码仓库或发布包。请不要上传 `credential.json`、SQLite 数据库、二维码、日志或运行目录。账号凭据和浏览记录仅由插件保存在 Host 提供的私有数据目录中。

本插件是第三方社区扩展，与哔哩哔哩官方无隶属关系。数据读取依赖 B 站接口和 `bilibili-api-python`，平台变化可能影响推荐、摘要、字幕及评论功能。平台拒绝或登录失效时，可在管理页查看原因。
